# ckpts/ — weights and upstream artifacts

Upstream-hosted artifacts are **link-only**: download them yourself, verify the hash, place
them exactly where the pipeline expects. Nothing upstream-hosted is committed to this repo
or rehosted elsewhere. The deploy bundle itself is generated locally by our converter, so
the only network fetches are the two small asset files and the fp32 source weights.

## Pipeline layout

There is exactly **one weight download** (the fp32 source). The deploy bundle is never
downloaded - the converter generates it locally (stage 2 of [run_pipeline.sh](../run_pipeline.sh)), so the
download table below has three rows, not four. The tree shows where files end up on disk;
the table shows what comes from the network.

```
ckpts/
├── pi05_libero_base/          # fp32 SOURCE - the one weight download (14.47 GB, 812 tensors)
│   └── model.safetensors      #   input to the converter only; the server never reads it, safe to delete after conversion
└── pi05_libero_official/      # DEPLOY dir - what the Orin server reads at runtime
    ├── model.safetensors      #   GENERATED by our converter (813 tensors, all BF16, 8.29 GB)
    ├── norm_stats.json        # downloaded (table row 2), 1914 B
    ├── meta.json              # generated by run_pipeline.sh (provenance record)
    └── assets/tokenizer/tokenizer.model   # downloaded (table row 3), 4.1 MB
```

## Deploy bundle (generated, not downloaded)

[scripts/export/convert_official_weights.py](../scripts/export/convert_official_weights.py) converts the fp32 source into the deploy bundle:
all 813 tensors BF16 (fp32→bf16 round-to-nearest-even), embed_tokens materialized from the
tied lm_head and inserted right after it, metadata dropped. The output is byte-identical to
the bundle used for every result in this repo (verified per-tensor against the production
bundle; output sha256 `41cb8647ac785f4fc4ccf0534479b7c97e3406d6c28e8bfe6536e2bb3b7c9ced`).
