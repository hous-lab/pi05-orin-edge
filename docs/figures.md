# Figures: what this repo shows, and how to make it read

The repo's argument is one sentence long - *pi0.5 runs at 92 ms on a Jetson AGX Orin
without losing LIBERO-10 accuracy* - and every figure has to earn its place against it.
This note records the visual system, the revision that produced the current set, and the
figures still worth adding.

## 1. The visual system

All figures are generated by five scripts and share one style module
([scripts/figstyle.py](../scripts/figstyle.py)):

| Element | Rule |
|---|---|
| Palette | navy `#1F3A5F` = client / laptop side, orange `#C2410C` = Orin / shipped recipe, blue `#1D4ED8` = plain data, green/amber/red = p50/p95/p99 severity |
| Type | one sans family; title 12.5 bold, body 9.5-10, footnotes 8.5-8.8 |
| Chrome | no top/right spines, faint horizontal grid only, no boxes around legends |
| Resolution | 180 dpi, sized so GitHub's 880 px column renders it at ~2x |
| Alt text | states the claim, not the file name |

Four content rules, applied to every figure:

1. **One figure, one question.** A topology figure answers "who runs what". A latency
   figure answers "how stable is it". Mixing them is how `113-150 ms` ended up next to
   `92.4 ms` and read as a contradiction.
2. **A number appears once.** If two panels carry the same value, one of them is
   decoration.
3. **No number without its caliber.** model p50, server infer and client p50 are three
   different measurements of the same run ([docs/recipe.md](recipe.md)); a figure that
   puts two of them side by side without saying so is a bug, not a comparison.
4. **Colour encodes what the labels already say.** Cell labels carry the values; colour
   is the gestalt only, so no colourbar is needed when every cell is numbered.

## 3. Still worth adding

Ordered by how much of the argument is currently carried by prose.

### Done in this revision

- **Demo contact sheet** ([make_demo_poster.py](../scripts/make_demo_poster.py)) - the
  six mp4 masters are in the repo but the README embeds GitHub user-attachment URLs,
  which do not survive a fork, a mirror or a clone-only reader. The sheet is the
  in-repo anchor and the fallback image.
- **Trade-off scatter** ([make_tradeoff.py](../scripts/make_tradeoff.py)) - the six-row
  table as one picture, with Wilson 95% CIs so the reader can see the vertical
  differences are inside sampling noise.
- **Pipeline diagram** ([make_pipeline.py](../scripts/make_pipeline.py)) - the four
  Get started steps split by machine, so the two-machine boundary is visible before
  the reader starts copying commands.

### Open, with their blockers

### P1 - the recipe waterfall

The engineering contribution (FAST_QUANT -5.6 ms, GEG8 -3.2 ms, K16 mix, the st8 fix)
lives in prose. A waterfall from BF16 to 92.4 ms would show it in one look.

Blocker: the BF16 row has no model-caliber p50 in the table (`-`), only a client p50 of
218.8-222.4 ms. Either measure BF16 at model caliber, or draw the waterfall in client
caliber for every step - not a mix of the two.

### P2 - quantization journey strip

[docs/quantization_journey.md](quantization_journey.md) documents the naive full-INT8
attempt that collapsed long-horizon tasks (task8 -48 pp, task9 -73 pp) and the K16
channel-split that fixed it. That is the most interesting failure in the repo and it is
currently text-only.

Blocker: no per-task records for the naive full-INT8 arm are committed, only the two
aggregate deltas in prose. The figure needs either those records or an explicit
"reconstructed from the prose" label.

### P3 - repo map as a layered diagram

The `Repo map` table is accurate but flat; the reader cannot see that
`flashrt_overlay/` sits inside `FlashRT`, which sits under `runtime/server_*.py`.
A three-layer diagram (upstream / our overlay / our harness) would carry that.

## 4. Known inconsistencies to settle

- **92.4 ms vs 10.7 Hz.** 92.4 ms is 10.8 Hz; 10.7 Hz is the 93.30 ms p50 of the tagged
  stats rerun (`benchmark/results/orin_gumix_geg8_stats_500ep/stats_500ep_orin.json`).
  The figures print `92.4 ms (10.8 Hz)` so the arithmetic holds. Pick one pair and use
  it everywhere, or state both runs explicitly.
- **Client p50 spread.** The primary arm's per-task client p50 spans 113.0-149.9 ms
  while the stats rerun sits flat at ~112.2 ms for all ten tasks. Worth one sentence in
  [docs/recipe.md](recipe.md): different transport path, or different client host load.

## 5. Regenerating

```bash
python3 scripts/make_overview.py            # assets/overview.png
python3 scripts/make_benchmark_figures.py   # assets/benchmarks/{latency_calibers,latency_timeline,task_success}.png
python3 scripts/make_tradeoff.py            # assets/benchmarks/tradeoff.png
python3 scripts/make_demo_poster.py         # assets/demos/poster_grid.png  (needs ffmpeg)
python3 scripts/make_pipeline.py            # assets/pipeline.png
```

Four of the five read the committed records under `benchmark/results/` (or the demo
masters) and write in place, so a figure can never drift from the data it claims to
show; `make_pipeline.py` is the one hand-laid-out diagram.
